# Замер: один прогон на все проверки

Скрипт нужен, чтобы новую голову GigaAM или новую версию движка проверять тем же
прогоном, а не переписанным заново. До сих пор каждый замер делался под случай и
выбрасывался, поэтому следующий начинался с нуля - и цифры двух замеров нельзя было
класть рядом.

Зависимостей сверх проекта нет: стандартная библиотека плюс `httpx`, который уже есть.
Скрипт разговаривает с консолью по HTTP, поэтому меряет ровно то, что увидит клиент:
прием загрузки, работу движка и ответ.

## A/B за шесть команд

```sh
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d       # 1
uv run python bench/bench.py run --audio ~/записи --label A \
  --deploy '{"variant":"e2e_rnnt","vad":false}'                              # 2
uv run python bench/bench.py run --audio ~/записи --label B \
  --deploy '{"variant":"e2e_rnnt","vad":true}'                               # 3
uv run python bench/bench.py compare bench/results/A.json bench/results/B.json  # 4
uv run python bench/bench.py compare bench/results/A.json bench/results/B.json --markdown  # 5
docker compose -f docker-compose.yml -f docker-compose.local.yml down        # 6
```

`--deploy` необязателен: без него меряется то, что уже развернуто. С ним скрипт ждет
`ready` и сверяет `/api/status` с тем, что просил, - иначе откат супервизора на
прежнюю голову подписал бы чужие цифры вашим ярлыком.

`--repeat` (по умолчанию 3) берет лучшее время из нескольких прогонов: первому мешает
все, от прогрева кеша до соседних процессов. `--api-key` нужен при заданном `API_KEY`,
`--url` - если консоль не на `localhost:8080`.

## Когда переменных больше одной

Настройку редко можно проверить в одиночку: параллельные окна движка работают только
при пуле от двух, а сам пул стоит времени. Два прогона тут ответа не дадут - выигрыш
параллельности сложится с проигрышем пула, и получится ничья, из которой ничего не
следует. Поэтому режимы берутся по решетке, и каждый лишний прогон изолирует ровно
одно слагаемое:

| метка | pool_size | file_window_concurrency | что изолирует |
|---|--:|--:|---|
| A `p1c1` | 1 | 1 | эталон, сегодняшнее умолчание |
| B `p2c1` | 2 | 1 | цену пула отдельно от параллельности |
| C `p2c2` | 2 | 2 | целевой режим |
| D `p1c2` | 1 | 2 | что делает флаг без свободного слота |

Дальше `compare A B`, `compare A C`, `compare A D` - все три от одного эталона, иначе
дельты не складываются. Замер 06.09.2026 сделан именно так, и половина выводов пришла
как раз из B и D, а не из целевого C.

Пик памяти скрипт не снимает: `memory.peak` контейнера из-под пользователя не
обнуляется, поэтому контейнер пересоздается перед каждым режимом, а число читается
после прогона из `/sys/fs/cgroup/.../memory.peak`.

`compare` считает по каждому файлу WER второго прогона относительно первого, нормализуя
обе стороны так же, как в [исследовании](../docs/research/head-choice-and-wer.md):
строчные, единая "е", знаки убраны, - иначе сравнение мерило бы запятые, а не слух.
Ниже таблицы он называет различающиеся места поименно: там видно, потерял ли прогон
смысловые слова или только переставил междометия. `--markdown` печатает ту же таблицу
для вставки в документ. `bench/results/` в git не попадает - в json лежат расшифровки
настоящих записей.

## Наборы, на которых мерили мы

Сами записи личные и в репозиторий не попадают - остаются только их длительности,
чтобы замер можно было повторить на своем материале сопоставимого размера.

| Замер | Записей | Длительности |
|---|--:|---|
| Встроенный словарь брендов, 04.09.2026 | 9 | от 9 с до 10 минут, суммарно 26.8 минуты |
| Кривая задержки и VAD, 04.09.2026 | 7 | 9 с, 36 с, 55 с, 71 с, 2.8 мин, 5.5 мин, 10.3 мин |
| Сверка версий движка, 04.09.2026 | 2 | 165 с и 265 с, плюс официальные примеры GigaAM |
| Параллельные окна, 06.09.2026 | 7 | 9 с, 36 с, 55 с, 71 с, 165 с, 328 с, 616 с (тот же набор, что 04.09) |
| Сверка версий движка, 06.09.2026 | 2 | 165 с и 265 с в WebM и их WAV-раскодировки, плюс примеры GigaAM |

Официальные примеры, которые не жалко скачать заново:

```sh
curl -sLO https://cdn.chatwm.opensmodel.sberdevices.ru/GigaAM/example.wav       # 11.3 с
curl -sLO https://cdn.chatwm.opensmodel.sberdevices.ru/GigaAM/long_example.wav  # 71.3 с
```

Выводы всех замеров - в [docs/research/head-choice-and-wer.md](../docs/research/head-choice-and-wer.md),
принятые по ним решения - в [docs/decisions.md](../docs/decisions.md).
