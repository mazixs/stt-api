# STT-консоль: локальное распознавание русской речи

Свой сервер распознавания речи с OpenAI-совместимым API. Поднимается одной
командой, моделью управляете через веб-страницу: выбрали голову GigaAM v3,
нажали «Развернуть» — API работает. Если что-то падает, поднимается само и
возвращается к последней рабочей конфигурации.

Внутри — модель [GigaAM v3](https://github.com/salute-developers/GigaAM) от
SberDevices и движок [gigastt](https://github.com/ekhodzitsky/gigastt) 2.18.0: один
Rust-бинарник на ONNX Runtime, INT8, без облака и без ключей к чужим сервисам.
Ни PyTorch, ни ffmpeg, ни CUDA не нужны — образ занимает 341 МБ. Версия движка
закреплена в `GIGASTT_TAG` и меняется только вместе с проверкой: два последних
обновления меняли поведение глоссария и набор принимаемых форматов.

![Веб-консоль](docs/console.png)

## Быстрый старт

```sh
git clone https://github.com/mazixs/stt-api.git && cd stt-api
cp .env.example .env          # необязательно: без .env возьмутся значения по умолчанию
docker compose up -d
```

Откройте `http://<адрес-сервера>:8091`, нажмите «Развернуть» на карточке
**GigaAM v3 RNN-T** и дождитесь статуса «готово». Первый раз качается ~230 МБ
весов, дальше они лежат в папке `models/` и не перекачиваются.

## Что получилось по скорости

Замеры на 16-ядерном настольном CPU, голова `rnnt` с пунктуацией, `POOL_SIZE=1`:

| Запись | Время распознавания | Быстрее реального времени |
|---|--:|--:|
| 11.3 с речи | 0.38 с | ×30 |
| 70.6 с речи | 2.82 с | ×25 |

Ваш сервер, скорее всего, медленнее — поэтому консоль **измеряет задержку сама**
на каждом запросе и показывает её в разделе «Статус». Ориентир по памяти:
контейнер в работе занимает ~120 МБ при `POOL_SIZE=1` (было ~600 МБ до движка
2.17.0, который перестал копировать веса энкодера в каждую сессию).

Для сравнения, WER на русском по
[замерам движка](https://github.com/ekhodzitsky/gigastt/blob/main/docs/benchmarks.md):
GigaAM v3 `rnnt` — 3.55% на чистой речи, `faster-whisper-turbo` — 14.45%.

## Модели

Выбираются в веб-консоли, переключение занимает пару секунд.

| Голова | Языки | Пунктуация | Когда брать |
|---|---|---|---|
| `rnnt` | ru | отдельным проходом RuPunct + ITN | по умолчанию: минимальный WER |
| `e2e_rnnt` | ru | встроена в модель | если не хотите отдельный проход пунктуации |
| `ml_ctc` | ru, en, kk, ky, uz | тем же проходом, но `PUNCTUATION=on` вручную | нужен не только русский, важна скорость |
| `ml_ctc_large` | ru, en, kk, ky, uz | так же вручную | те же языки, точнее и медленнее |

Если диктуете техническую речь с английскими терминами, голову выбирает алфавит. В
словаре `rnnt` латиницы нет вообще, поэтому «GigaAM» в лучшем случае выйдет
транслитом. У мультиязычных голов латиница есть, а у `e2e_rnnt` есть ещё заглавные,
цифры и дефисы. Один и тот же файл, 165 секунд диктовки про WebM и Opus:

| | `rnnt` + RuPunct | `ml_ctc` + RuPunct | `e2e_rnnt` |
|---|---|---|---|
| «утопия» | утопия | утоп**ие** | утопия |
| «чтобы это работало» | чтобы это работало | чтоб **ЭО** работало | чтоб это работало |
| «транскрибацию» | транс**греб**ацию | транскрибацию | транскр**е**бацию |
| «во-первых» | во первых | во первых | **во-первых** |
| «сто процентов» | 100 процентов | 100 процентов | **100%** |
| «GigaAM» / «WebM» | Гигаэм / — | гигаэм / веб | Гигам / веб-М |
| латиница в выводе | нет | только целиком английские фразы | есть |
| память контейнера | 121 МиБ | 130 МиБ | **91 МиБ** |
| 165 с звука | 6.3 с | **5.8 с** | 6.6 с |

`e2e_rnnt` выигрывает там, где видно глазу: дефисы, проценты, заглавные, латиница —
и вдобавок легче всех по памяти, ей не нужен ни отдельный проход пунктуации, ни его
модель. Платит за это скоростью: `ml_ctc` быстрее примерно на 12%, и на отдельных
словах точнее. Точного написания английских терминов не даёт ни одна голова,
глоссарий тут тоже не спасает (см. ниже).

`ml_ctc_large` в таблицу не попала намеренно: она точнее `ml_ctc`, но вдвое
медленнее `e2e_rnnt` (11.2 с против 6.6 с на том же файле), пишет так же голо и
весит 564 МБ. Берите её, только если действительно нужны пять языков.

Цифры — движок 2.17.0, лучшее из трёх прогонов, `POOL_SIZE=1`. Память упала против
прежних 0.7–1.1 ГБ: движок больше не копирует веса энкодера в каждую сессию, а читает
их из общего отображения файла.

Мультиязычного RNN-T не существует: `ai-sage/GigaAM-Multilingual` выпущена только
с CTC-декодерами (220M и 600M), поэтому выбор между русской и мультиязычной
линейкой — это выбор языков и скорости против качества на русском. Глоссарий с
2.17.0 работает на обеих.

### Почему не голова с верхних строчек лидерборда

В [независимом лидерборде](https://huggingface.co/spaces/ESpeech/russian_asr_leaderboard)
Николая Шмырева `rnnt` стоит второй, а `e2e_rnnt` — девятой. Мы это перепроверили
собственным замером на русском FLEURS: лидерборд усредняет разговорную и телефонную
речь, а на технической диктовке `e2e_rnnt` точнее при любом способе подсчёта — и она
одна умеет писать то, чем полон глоссарий. Разбор, цифры и оговорки о применимости —
в [docs/research/head-choice-and-wer.md](docs/research/head-choice-and-wer.md).

## Как подключить

API совместим с OpenAI, поэтому подходит любой клиент, умеющий `base_url`:

```sh
curl -X POST http://<сервер>:8091/v1/audio/transcriptions \
  -F model=whisper-1 \
  -F file=@запись.wav
```

```python
from openai import OpenAI

client = OpenAI(base_url="http://<сервер>:8091/v1", api_key="не-нужен")
with open("запись.wav", "rb") as audio:
    print(client.audio.transcriptions.create(model="whisper-1", file=audio).text)
```

Поддерживается: `response_format` = `json`, `text`, `srt`, `vtt`, `verbose_json`;
`timestamp_granularities[]` = `word` / `segment`; `stream=true` (SSE с
промежуточным текстом); форматы аудио WAV, MP3, M4A/AAC, OGG/Vorbis, OGG/Opus,
FLAC и WebM/Opus. Поле `model` можно передавать любое — работает та голова,
которую вы развернули; `GET /v1/models` покажет список.

WebM/Opus — это то, что пишут браузеры и Electron-приложения через `MediaRecorder`
(OpenWhispr, например). До движка 2.17.0 такая запись отвергалась с 422, и консоль
переупаковывала её сама; теперь она доходит до движка байт в байт
([история](docs/decisions.md)).

Не поддерживается: `/v1/audio/translations` (GigaAM не переводит речь) и поле
`prompt` — контекст задаётся глоссарием, см. ниже.

Кроме OpenAI-пути наружу проброшены родные эндпоинты движка: `/v1/transcribe`
(диаризация, телефонные кодеки, экспорт), `/v1/transcribe/stream`, `/v1/jobs`
(включается `ENABLE_JOBS=1`).

### Что торчит наружу

| Путь | Ключ | Что делает |
|---|---|---|
| `POST /v1/audio/transcriptions` | да | Распознавание, OpenAI-совместимое |
| `GET /v1/models` | да | Четыре головы плюс `whisper-1` для клиентов с зашитым именем |
| `POST /v1/audio/translations` | да | Всегда `400`: GigaAM не переводит речь |
| `GET/POST/DELETE /v1/...` | да | Проброс остальных родных эндпоинтов движка |
| `GET /api/status`, `/api/models`, `/api/glossary` | да | Данные для веб-консоли |
| `POST /api/deploy`, `/api/stop`, `/api/glossary` | да | Развернуть голову, остановить движок, применить глоссарий |
| `POST /api/test` | да | Разовое распознавание с замером времени и RTF |
| `GET /api/events` | да | SSE: статус, прогресс скачивания, логи |
| `GET /health` | нет | Живость самой консоли, сюда смотрит healthcheck Docker |
| `GET /api/docs`, `/api/openapi.json` | нет | Схема API; описание эндпоинтов видно и без ключа, сами вызовы — нет |

Ключ передаётся как `Authorization: Bearer <ключ>`. Исключение одно: `EventSource`
в браузере не умеет заголовки, поэтому `/api/events` принимает ещё и `?api_key=`.

## Начальный контекст (глоссарий)

Имена, термины и названия, которые должны распознаваться правильно, задаются в
`.env` переменной `INITIAL_CONTEXT` или прямо в веб-консоли:

```
INITIAL_CONTEXT=АйМоп, GigaAM|8, Пётр Иванович Сидоров
```

Разделители — запятая или перевод строки, вес фразы — после вертикальной черты
(больше вес — настойчивее подсказка, общая сила — `HOTWORDS_BOOST`). Это
hotword-биасинг: подсказка работает **на этапе декодирования**, а не правкой
готового текста. Правка глоссария в консоли применяется без перезапуска —
движок перечитывает список на месте.

В консоли список выглядит как набор фраз: каждая — отдельная плашка с крестиком,
новая добавляется по Enter или запятой, повтор не добавится (сравнение как у движка —
регистр и «ё» не делают фразу новой). Плашка той фразы, которую выбранная голова
написать не может, зачёркнута — то есть видно поимённо, что движок выбросит.

Форматирование берёт на себя сервис: вставляйте как есть, хоть через запятую, хоть
списком — повторы схлопнутся, лишние пробелы уйдут, вес разберётся. Правки копятся,
пока не нажмёте «Применить»: каждое применение заставляет движок перечитать список, и
делать это на каждый крестик незачем. Кнопки **Импорт** и **Экспорт** работают со
всем списком, импорт дописывает к тому, что уже есть. Копию стоит забирать время от
времени: список живёт в томе `data/`, и другого экземпляра у него нет.

`HOTWORDS_DEFAULT=1` дополнительно включает встроенный словарь русских брендов
и аббревиатур движка.

Работает глоссарий на всех четырёх головах: с 2.17.0 CTC-головы получили лучевой
поиск по префиксам, и подсказка на них наконец действует.

**Фразу выбрасывают, если голова не может её написать.** Регистр тут не при чём —
движок сам пробует фразу как написана, потом строчными, потом с «е» вместо «ё», — а
вот чужой алфавит не спасает ничто:

| Голова | Алфавит | `OpenWhispr` |
|---|---|---|
| `rnnt` | 32 строчные кириллические буквы | недостижим, пишите «опенвиспр» |
| `ml_ctc` | + латиница и апострофы | пройдёт |
| `e2e_rnnt` | 1025 BPE-токенов, 147 символов: заглавные, латиница, цифры, пунктуация | пройдёт как написан |

Движок называет отброшенные фразы в логе, а консоль показывает их же рядом с
полем глоссария — вместе с тем, сколько фраз доживёт до декодера.

`HOTWORDS_BOOST=5.0` — значение самого движка, и на 2.17.0 оно безопасно: глоссарий,
чьих слов в записи нет, оставляет текст побайтово тем же. Поднимать выше стоит только
если нужное слово всё равно не узнаётся.

Чего от глоссария ждать не стоит: точного написания английских терминов. На
`e2e_rnnt` фразы `GigaAM` и `WebM` принимаются как написаны, но «Гигам» от этого
превращается в «GIM» или «Gigam», а не в «GigaAM». Глоссарий смещает вероятности,
а не подставляет строки. Правило, проверенное на живой записи: **подсказка дотягивает
почти угаданное и не выдумывает неуслышанное.** `H20` → `H200` она поправила, а
`standart Bird` в `Thunderbird` не превратила ни при каком бусте — при 20 движок вместо
этого начал притягивать соседей по списку и выдал `Standart Blackwird`
([разбор](docs/research/head-choice-and-wer.md)).

Английские названия, которых движок не расслышал, надёжнее чинить проходом по готовому
тексту — в OpenWhispr это режим с языковой моделью, он же убирает «э-э-э».

## Настройки `.env`

Полный список с пояснениями — в [`.env.example`](.env.example). Главное:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `HOST_PORT` | `8091` | Порт на сервере |
| `API_KEY` | пусто | Если задан — нужен `Authorization: Bearer <ключ>` для API и консоли |
| `INITIAL_CONTEXT` | пусто | Глоссарий |
| `MODEL_VARIANT` | `rnnt` | Что предвыбрано в консоли |
| `PUNCTUATION` / `ITN` | `auto` | Пунктуация и числа цифрами |
| `VAD` | `0` | Пропуск тишины, полезно для длинных записей |
| `POOL_SIZE` | `1` | 1 = минимальная задержка (лучшее для диктовки) |
| `AUTOSTART` | `1` | Поднимать последнюю модель при старте контейнера |
| `MAX_UPLOAD_MB` | `50` | Лимит размера файла |
| `HF_TOKEN` | пусто | Не нужен: веса берутся с GitHub Releases, а не с Hugging Face |

Значения `.env` — это то, что предвыбрано в консоли. Конкретную голову вы
выбираете кнопкой, и она запоминается: после `docker compose restart` сервис
сам поднимет её обратно.

**Отсюда следствие, которое стоит знать до первой правки:** после первого
развёртывания приоритет у `data/state.json`, а не у `.env`. Правка `MODEL_VARIANT`
или `POOL_SIZE` в `.env` сама по себе ничего не изменит в работающем движке — нужно
нажать «Развернуть» в консоли (или сделать `POST /api/deploy` с явными значениями).
Что развёрнуто на самом деле, видно в `ps -eo args | grep "gigastt serve"`.
Переменные окружения консоли (`API_KEY`, `MAX_UPLOAD_MB`, `HOST_PORT`, `AUTOSTART`)
читаются при старте контейнера и в состоянии не хранятся.

## Что происходит при падениях

| Что упало | Что делает сервис |
|---|---|
| Процесс движка | Консоль поднимает его заново с задержкой 1, 2, 4, 8, 16, 30 с; после пяти неудач подряд — раз в минуту, пока не поднимется |
| Контейнер целиком | Docker перезапускает (`restart: unless-stopped`), конфигурация читается из `data/state.json` |
| Скачивание весов оборвалось | Два повтора, потом понятная ошибка в консоли и кнопка «Развернуть» для новой попытки. Работающая модель при этом не останавливается |
| Новая голова не запустилась | Автоматический откат на предыдущую рабочую |

Запросы, попавшие точно в момент падения, теряются — клиент должен повторить.
Пока движок не готов, API отвечает `503` с заголовком `Retry-After`.

Контейнеру заданы потолок памяти в 3 ГБ и ротация логов (три файла по 10 МБ) — обе
настройки в `docker-compose.yml` с обоснованием в комментариях и в
[docs/decisions.md](docs/decisions.md). Потолок посчитан не по рабочим ~120 МиБ, а по
самому тяжёлому мигу — пересборке оптимизированного графа после смены головы: 1078 МиБ
для `e2e_rnnt` и 2538 МиБ для `ml_ctc_large`. Процессор намеренно не ограничен.

## Где что лежит

| Путь | Что |
|---|---|
| `models/` | Веса моделей: голова (~230 МБ), пунктуация (~31 МБ), диаризация (~27 МБ) |
| `models/optimized_cache/` | Оптимизированные графы ONNX, ~300 МБ на развёрнутую голову. Убираются командой движка `cache-gc`, с 2.18.0 она не трогает нужные ([разбор](docs/decisions.md)) |
| `data/state.json` | Последняя развёрнутая конфигурация |
| `data/hotwords.txt` | Глоссарий в формате движка |
| `data/metrics.json` | Счётчики консоли: сколько файлов, секунд звука и времени распознавания |

Наружу открыт только порт консоли. Движок слушает `127.0.0.1:9876` внутри
контейнера, поэтому попасть в него можно лишь через консоль, которая проверяет
API-ключ.

## Если что-то пошло не так

**Скачивание обрывается на середине.** Файл весов — 225 МБ; при нестабильной
сети движок может получить обрыв TLS. Сервис делает два повтора сам. Если не
помогает, скачайте четыре файла руками с
[релиза движка](https://github.com/ekhodzitsky/gigastt/releases) и положите в
`models/`: `v3_rnnt_encoder_int8.onnx`, `v3_rnnt_decoder.onnx`,
`v3_rnnt_joint.onnx`, `v3_vocab.txt` (для `e2e_rnnt` — файлы с префиксом
`v3_e2e_rnnt_`). Консоль увидит их и запустится без скачивания.

**Кнопка «Записать с микрофона» не работает.** Браузеры дают доступ к микрофону
только на `localhost` или по HTTPS. Либо откройте консоль через SSH-туннель
(`ssh -L 8091:localhost:8091 сервер`), либо поставьте перед сервисом обратный
прокси с сертификатом. Распознавание файлов при этом работает всегда.

**Логи.** `docker compose logs -f` — там же вывод движка. Последние строки видны
в консоли в разделе «Логи».

**Занят порт.** Поменяйте `HOST_PORT` в `.env` и `docker compose up -d`.

## Как это устроено

Консоль владеет процессом движка, а не соседствует с ним: `gigastt serve` — её
дочерний процесс на `127.0.0.1:9876`, наружу не публикуется. Своей сборки Rust в
проекте нет, бинарник берётся из образа апстрима.

| Файл | За что отвечает |
|---|---|
| `console/main.py` | Сборка приложения: `Settings` → `Supervisor` → FastAPI, три роутера и статика с отпечатком содержимого в ссылках |
| `console/supervisor.py` | Машина состояний (`stopped` / `downloading` / `starting` / `ready` / `error`), откат на последнюю рабочую конфигурацию, сторож упавшего процесса |
| `console/engine.py` | Жизненный цикл `gigastt serve`: единственное место, где собираются аргументы движка |
| `console/downloader.py` | Скачивание весов командой самого движка, прогресс и контрольные суммы — его же |
| `console/api.py` | Управляющий API консоли под `/api` |
| `console/proxy.py` | Фасад OpenAI: ключ, лимит размера, понятные ошибки при неготовности, замер времени. Тело загрузки уходит в движок байт в байт, ответ движка не переписывается |
| `console/auth.py` | Проверка `Authorization: Bearer`, выключена при пустом `API_KEY` |
| `console/state.py` | `data/state.json`, запись атомарная: контейнер, убитый на середине, не найдёт обрывок |
| `console/catalog.py` | Четыре головы: названия, размеры, файлы весов для значка «скачано» |
| `console/vocab.py` | Читает словарь головы с диска и отвечает, какие фразы глоссария движок сможет написать, повторяя его каскад: как написано → строчными → «е» вместо «ё» |
| `console/glossary.py` | Разбор списка фраз в формат движка (`data/hotwords.txt`) |
| `console/events.py` | Шина событий, из которой берётся SSE `/api/events` |
| `console/metrics.py` | Счётчики в `data/metrics.json` |
| `console/wavinfo.py`, `console/webminfo.py` | Длительность WAV и WebM/Opus без декодирования — только ради RTF, звук не трогают |
| `console/static/` | Фронтенд без сборки и зависимостей: `index.html`, `app.js`, `style.css`. Запись с микрофона собирается в WAV прямо в браузере, поэтому в образе не нужен ffmpeg |

## Разработка

```sh
uv sync          # окружение
uv run pytest    # тесты; движок подменяется заглушкой, ничего не качается
```

Поднять сервис на своей машине лучше через наложение — тогда контейнер не будет
воскресать сам после перезагрузки и не спутается с боевым по имени:

```sh
cp .env.local.example .env.local
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.local.yml down    # не забыть
```
