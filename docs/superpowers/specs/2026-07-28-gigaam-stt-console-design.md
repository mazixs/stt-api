# STT-консоль над GigaAM (GigaSTT) — дизайн

Дата: 2026-07-28
Статус: утверждён

## Цель

Локальный сервис распознавания русской речи, который поднимается одной командой
`docker compose up -d`, показывает веб-морду, где выбирается конкретная голова
GigaAM v3, и после нажатия «Развернуть» отдаёт OpenAI-совместимый API. Основной
сценарий — диктовка текста, поэтому задержка важнее пропускной способности.
Сервер: LXC на Proxmox, только CPU и оперативная память, GPU не будет.

## Ключевое решение: инференс не пишем

Инференс берём готовый — [gigastt](https://github.com/ekhodzitsky/gigastt) (MIT,
Rust, ONNX Runtime, образ `ghcr.io/ekhodzitsky/gigastt:2.15.0`, amd64+arm64).
Движок уже умеет:

- `POST /v1/audio/transcriptions` — OpenAI-совместимый, форматы `json` / `text` /
  `srt` / `vtt` / `verbose_json`, `timestamp_granularities[]`, SSE при `stream=true`;
- сам скачивает GigaAM v3 с HuggingFace и квантует в INT8 (~225 МБ), холодный
  старт ~0.94 с, RTF ~0.10 на CPU;
- пунктуацию, регистр и ITN (числа словами → цифры): нативно на голове
  `e2e_rnnt` либо проходом RuPunct + ITN на `rnnt`;
- **нативный hotword-биасинг** на этапе декодирования (`--hotwords-file`:
  фраза на строку, опционально `\t<вес>`; `--hotwords-boost`;
  `--hotwords-default` — встроенный словарь русских брендов и аббревиатур);
- VAD, диаризацию, очередь задач `/v1/jobs`, WebSocket с инкрементальными
  partial'ами, rate-limit по IP, `/health`, горячую перезагрузку
  `POST /v1/admin/reload` (только с loopback);
- машиночитаемый прогресс скачивания: `gigastt download --progress json` пишет
  в stdout NDJSON (`phase`: `download` / `verify` / `quantize` / `done` / `error`).

Что движок **не** умеет и делаем мы: веб-интерфейс, выбор и переключение головы,
`GET /v1/models`, аутентификацию по API-ключу, управление глоссарием,
персистентность конфигурации, автоподъём после падения, статистику задержек.

Отвергнутые варианты: официальный `gigaam` на PyTorch (RTF 0.3–0.5 на CPU,
образ ~4 ГБ, HTTP-слоя нет), `onnx-asr` и `transcribe.cpp` (быстрые движки, но
сервера нет), Triton из репозитория Сбера (заточен под GPU/TensorRT).

## Архитектура

Один контейнер, два процесса. Доступ к docker-сокету не нужен.

```
контейнер stt-api  (restart: unless-stopped, init: true)
│
├── console — Python 3.13 / FastAPI, слушает 0.0.0.0:8080
│     ├── веб-интерфейс (статика, без сборки)
│     ├── /api/*  — управление
│     ├── /v1/*   — OpenAI-фасад: проверка API-ключа → проксирование в движок
│     └── супервизор дочернего процесса
│
└── gigastt serve — дочерний процесс, слушает 127.0.0.1:9876 (наружу не публикуется)
```

Границы ответственности: консоль никогда не декодирует аудио сама и не парсит
модели. Всё, что касается инференса, — только флаги и HTTP-вызовы движка.

## Компоненты консоли

| Модуль | Ответственность |
|---|---|
| `console/settings.py` | Чтение `.env` в типизированный `Settings` (pydantic-settings) |
| `console/catalog.py` | Метаданные голов: id, человеческое имя, язык, пунктуация из коробки, ориентировочный размер и скорость |
| `console/state.py` | `/data/state.json`: желаемая конфигурация, последняя рабочая (`last_good`), статус. Атомарная запись через временный файл + `os.replace` |
| `console/engine.py` | Сборка argv/env для `gigastt serve`, запуск, остановка (SIGTERM + drain, затем SIGKILL), опрос `/health` |
| `console/downloader.py` | Запуск `gigastt download --progress json`, разбор NDJSON в события прогресса, коды выхода (65 — контрольная сумма, 69 — сеть, 74 — диск) |
| `console/supervisor.py` | Автомат развёртывания, watchdog, авто-откат, backoff |
| `console/glossary.py` | `INITIAL_CONTEXT` и правки из UI → `/data/hotwords.txt`, вызов `/v1/admin/reload` |
| `console/proxy.py` | Проксирование `/v1/*` в движок: multipart без буферизации целиком, SSE-стриминг, свой `GET /v1/models` |
| `console/auth.py` | `Authorization: Bearer <API_KEY>`, если ключ задан |
| `console/metrics.py` | Кольцевая статистика запросов: длительность аудио, время обработки, RTF |
| `console/events.py` | Шина событий для SSE + кольцевой буфер логов |
| `console/static/` | Одностраничный интерфейс на ванильном JS |

## Автомат развёртывания

Статусы: `stopped` → `downloading` → `starting` → `ready`, и `error` из любого.

`POST /api/deploy {variant, punctuation, itn, vad, pool_size}`:

1. Желаемая конфигурация пишется в `state.json`, статус `downloading`.
2. Если файлов головы нет в `/models` — `gigastt download --model-variant <V>
   --model-dir /models --progress json`; NDJSON транслируется в UI через SSE.
   Ошибка скачивания → статус `error` с человеческим текстом, ранее работавший
   движок **не** останавливается.
3. Старый дочерний процесс останавливается (SIGTERM, ожидание drain до 15 с).
4. Запускается новый с новыми флагами, статус `starting`.
5. Опрос `/health` до `status == "ok"` и `model != "loading"`, таймаут 180 с.
6. Успех → статус `ready`, конфигурация копируется в `last_good`.
   Неудача → одна автоматическая попытка вернуться на `last_good`; если и она
   не поднялась → `error` с текстом и предложением выбрать другую голову.

Смена только глоссария не рестартит процесс: файл перезаписывается и вызывается
`POST /v1/admin/reload` (мы на loopback внутри контейнера, ограничение движка
соблюдено). Если reload вернул ошибку — падаем на полный рестарт процесса.

Watchdog: если процесс умер при статусе `ready`, перезапуск с backoff
1, 2, 4, 8, 16, 30 с (дальше каждые 30 с). После пяти неудач подряд статус
`error`, но попытки продолжаются раз в 60 с. Все события — в лог и в UI.

## Восстановление после падения

Три уровня, каждый проверяется тестом или ручным сценарием:

1. Движок упал → watchdog консоли поднял (секунды).
2. Консоль упала → Docker поднял контейнер (`restart: unless-stopped`), при
   старте читается `state.json` и последняя конфигурация разворачивается
   автоматически, если `AUTOSTART=1` (по умолчанию).
3. Веса и модели лежат в томе `./models`, повторно не скачиваются.

Незавершённые в момент падения запросы теряются — клиент повторяет. Гарантий
доставки не делаем, это осознанное упрощение.

## API консоли

Управление (защищено тем же API-ключом, если он задан):

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/status` | Статус, текущая и желаемая конфигурация, версия движка, статистика задержек |
| GET | `/api/models` | Каталог голов + признак «скачано» |
| POST | `/api/deploy` | Развернуть голову с опциями |
| POST | `/api/stop` | Остановить движок (статус `stopped`, сохраняется) |
| GET | `/api/glossary` · POST | Прочитать / заменить список фраз |
| GET | `/api/events` | SSE: смены статуса, прогресс скачивания, строки лога |
| POST | `/api/test` | Файл или запись из UI → распознавание + замер времени |
| GET | `/health` | Живость консоли: всегда 200, если процесс жив; внутри — статус движка |

Docker healthcheck смотрит на `/health` консоли и **не** учитывает статус
движка — иначе неразвёрнутая модель уводила бы контейнер в цикл перезапусков.

OpenAI-фасад: `POST /v1/audio/transcriptions` (проксируется как есть, включая
`stream=true` и все `response_format`), `POST /v1/audio/translations` → 400 с
пояснением, что GigaAM не переводит, `GET /v1/models` — наш, отдаёт головы в
формате OpenAI плюс алиас `whisper-1`. Пока движок не готов — 503 с
`Retry-After`. Поле `prompt` движок принимает и игнорирует; в README и в UI
честно написано, что контекст задаётся глоссарием, а не `prompt`.

## Конфигурация (.env)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `CONSOLE_PORT` | `8080` | Порт веб-морды и API |
| `API_KEY` | пусто | Если задан — обязателен `Authorization: Bearer`. Пусто → открыто, в UI баннер |
| `MODEL_VARIANT` | `rnnt` | Голова при первом старте: `rnnt`, `e2e_rnnt`, `ml_ctc`, `ml_ctc_large` |
| `PUNCTUATION` | `auto` | `auto` / `on` / `off` |
| `ITN` | `auto` | Числа словами → цифры |
| `VAD` | `0` | Пропуск тишины; полезно для длинных файлов |
| `POOL_SIZE` | `1` | Сессий инференса. 1 = минимальная задержка, ~400 МБ RAM |
| `INITIAL_CONTEXT` | пусто | Глоссарий: фразы через запятую или перевод строки, вес через `\|` (`АйМоп\|8`) |
| `HOTWORDS_BOOST` | `5.0` | Сила биасинга |
| `HOTWORDS_DEFAULT` | `0` | Добавить встроенный словарь брендов и аббревиатур |
| `AUTOSTART` | `1` | Разворачивать последнюю конфигурацию при старте контейнера |
| `MAX_UPLOAD_MB` | `50` | Лимит размера файла |
| `ENABLE_JOBS` | `0` | Асинхронная очередь движка для длинных файлов |
| `HF_TOKEN` | пусто | Пробрасывается в движок. При реализации проверяется, читает ли он токен; если нет — в README отмечается, что переменная не нужна |
| `LOG_LEVEL` | `info` | Уровень логов консоли и движка |

## Веб-интерфейс

Одна страница, ванильный JS, без сборки, тёмная и светлая темы по системной.

1. **Статус** — пилюля (`не развёрнуто` / `качаю модель 43%` / `запускаю` /
   `готово` / `ошибка`), текущая голова, аптайм, средняя задержка по последним
   20 запросам, признак наличия API-ключа.
2. **Модели** — карточки голов: имя, язык, «пунктуация из коробки», размер,
   отметка «скачано», кнопка «Развернуть». Тумблеры пунктуации, ITN, VAD и
   размера пула — рядом, с подсказками.
3. **Проверка** — перетаскивание файла и запись с микрофона (в браузере PCM
   собирается в WAV на месте, чтобы не тащить ffmpeg в образ). Показывает текст,
   время обработки и RTF.
4. **Глоссарий** — текстовое поле, кнопка «Применить» (перезагрузка движка без
   рестарта процесса).
5. **Подключение** — готовые сниппеты curl и Python-SDK с подставленным адресом
   и ключом.
6. **Логи** — последние строки, живые через SSE.

## Docker

Один `Dockerfile`, база `debian:trixie-slim` (совпадает с базой образа движка,
поэтому его бинарник линкуется без сюрпризов с glibc/libstdc++), внутрь
кладётся Python 3.13 из репозитория Debian и `COPY --from=ghcr.io/ekhodzitsky/gigastt:2.15.0
/usr/local/bin/gigastt`. Итоговый размер ~400 МБ. Никаких torch, ffmpeg, pyannote.

`docker-compose.yml` — один сервис, `init: true` (корректная жатва дочернего
процесса), `restart: unless-stopped`, healthcheck на `/health`, публикуется
только порт консоли. Тома: `./data` → `/data` (состояние, глоссарий, логи),
`./models` → `/models` (веса, ~1.5 ГБ). GPU не предусматриваем: если он появится,
меняется базовый образ движка на `-cuda` — отдельная задача, не эта.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Файл больше `MAX_UPLOAD_MB` | 413 в формате ошибки OpenAI |
| Движок не готов | 503 + `Retry-After`, в UI понятный статус |
| Скачивание: сеть / контрольная сумма / диск | Разные сообщения по коду выхода, кнопка «Повторить», работающий движок не трогаем |
| Пул занят | Пробрасываем 503 движка с `retry_after_ms` |
| Неизвестный формат аудио | Пробрасываем 400 движка со списком поддерживаемых форматов |
| Нет API-ключа при заданном `API_KEY` | 401 в формате OpenAI |

## Тестирование

Разработка через тесты. Движок в автотестах не запускается: подменяется
двумя заглушками — HTTP-стабом (`/health`, `/v1/audio/transcriptions`,
`/v1/admin/reload`) и фальшивым CLI (`download` печатает NDJSON, `serve`
поднимает стаб), путь к бинарнику приходит из `ENGINE_BIN`.

Покрываем: контракт OpenAI-фасада и все `response_format`; авторизацию;
`GET /v1/models`; автомат развёртывания, включая ошибку скачивания и
авто-откат; watchdog и backoff; персистентность и восстановление из
`state.json`; генерацию `hotwords.txt` из `INITIAL_CONTEXT` (запятые, переводы
строк, веса, дубликаты); лимит размера; SSE-события.

Отдельно `docs/manual-smoke.md` — ручной прогон на живом движке: развернуть
`rnnt`, надиктовать в UI, проверить пунктуацию, убить процесс движка и увидеть
автоподъём, перезапустить контейнер и увидеть восстановление конфигурации.

## Риски и решения

| Риск | Решение |
|---|---|
| Движок — молодой проект (33 звезды, фактически один автор) | Пиним образ по версии `2.15.0`; консоль общается с движком по HTTP, поэтому замена на `onnx-asr` не затрагивает UI и API; модели — стандартный ONNX-экспорт GigaAM |
| Смена головы = 1–3 с недоступности | UI показывает статус; клиенты получают 503 + `Retry-After` |
| Скорость на конкретном CPU неизвестна | `POOL_SIZE=1` по умолчанию; консоль измеряет реальные RTF и показывает их в UI — решение о голове принимается по факту, а не по обещаниям |
| `HF_TOKEN` может не читаться движком | Проверяется при реализации, результат честно фиксируется в README |
| Дочерний процесс осиротеет при падении PID 1 | `init: true` в compose, обработка SIGTERM в консоли с остановкой ребёнка |

## Вне области

Диаризация, телефонные кодеки, асинхронные задачи и мультиязычные головы
доступны в движке и включаются флагами, но отдельного интерфейса под них не
делаем. Обучение и дообучение моделей, кластеризация, несколько
одновременно загруженных голов, GPU-профиль — не в этой работе.
