# О продукте

Для кого и на что рассчитан сервис. Инструкции по запуску — в корневом
[README](../README.md), этот файл про рамки, а не про кнопки.

## Задача

Один человек диктует по-русски и хочет получить готовый текст примерно за секунду.
Диктовка — техническая: названия моделей видеокарт, телефонные термины, имена
инструментов, много латиницы и цифр. Текст затем вставляется в переписку или
документ как есть, поэтому важна не только правильность слов, но и то, как они
записаны: заглавные, дефисы, знак процента, числа цифрами.

Клиент — [OpenWhispr](https://github.com/dsdanielpark/OpenWhispr) на Electron,
указывающий на наш `base_url`. Он пишет звук браузерным `MediaRecorder`, то есть
WebM/Opus 48 кГц, и другого формата предложить не может.

**Клиент не стримит, и это не наша настройка.** Разобрано по исходникам v1.9.2 от
29.08.2026: `shouldUseStreaming()` в `src/helpers/audioManager.js` возвращает `false`
для self-hosted, поэтому запись уходит одним `POST` после остановки, целиком, без
клиентского таймаута и без разбиения. Следовательно ожидание пользователя равно RTF,
умноженному на длительность записи, - живой поток со стороны консоли делать незачем,
клиент его просто не использует. Ускорять можно только сам файловый путь.

**И к нашему времени клиент добавляет свое.** После транскрипции OpenWhispr по
умолчанию (`useCleanupModel: true`) гонит текст через LLM-очистку, последовательно и
уже после нашего ответа. Секунды, которые видит человек, - это наши плюс ее (issues
[#1761](https://github.com/OpenWhispr/openwhispr/issues/1761),
[#1207](https://github.com/OpenWhispr/openwhispr/issues/1207)). Сколько именно стоит
очистка, мы не мерили: это чужая сторона.

## Что из этого следует

**Задержка важнее пропускной способности.** `POOL_SIZE=1` по умолчанию: одна
сессия, минимальное время ответа. Консоль измеряет задержку на каждом запросе и
показывает её, вместо того чтобы ссылаться на чужие бенчмарки.

**Только CPU и память.** Сервис живёт в LXC-контейнере на Proxmox, GPU нет и не
планируется. Все веса — INT8, все замеры сняты на CPU.

**Простота дороже гибкости.** Одна голова развёрнута в один момент времени,
переключение — кнопкой в консоли. Ни очередей, ни балансировки, ни второго
процесса; чем меньше деталей, тем меньше того, что придётся понимать при поломке.

**Домашняя сеть.** Ключ API опционален, наружу открыт только порт консоли, движок
слушает loopback внутри контейнера.

## Чего сервис не делает

Не переводит речь: `/v1/audio/translations` отвечает понятной ошибкой, GigaAM
только распознаёт. Не принимает поле `prompt` — контекст задаётся глоссарием.
Не даёт точного написания английских терминов: глоссарий смещает вероятности, а не
подставляет строки, поэтому «Гигам» скорее станет «Gigam», чем «GigaAM».
Не умеет потоковую диктовку по WebSocket со стороны консоли — родной эндпоинт
движка проброшен, но своей обвязки для него нет.

Микрофон в веб-консоли работает только на `localhost` или по HTTPS — это
ограничение браузеров, не наше. Через SSH-туннель работает.

## Что дальше, если понадобится
