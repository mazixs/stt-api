# Repository Guidelines

## Структура проекта

- `console/` — Python-пакет сервиса: сборка FastAPI находится в `main.py`, управление движком — в `supervisor.py`, жизненный цикл `gigastt` — в `engine.py`, маршруты — в `api.py` и `proxy.py`.
- `console/static/` — веб-консоль (`index.html`, `app.js`, `style.css`) без отдельной сборки и npm-зависимостей.
- `tests/` — тесты `pytest`; `tests/fake_gigastt.py` заменяет реальный движок.
- `docs/` — продуктовые рамки, технические решения, исследования и ручной smoke-тест. `data/` и `models/` — локальные тома и не коммитятся.

## Команды разработки

```sh
uv sync                                      # создать/обновить .venv
uv run pytest                                # весь набор тестов
uv run pytest tests/test_vocab.py -q         # один файл
uv run pytest -k glossary                    # тесты по имени
cp .env.local.example .env.local
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.local.yml down
```

Локальный Compose-стек используйте вместе с `.env.local`: так контейнер не будет автоматически запускаться после перезагрузки. Ручной сценарий с настоящими весами описан в `docs/manual-smoke.md`.

## Стиль и именование

Проект требует Python 3.12 и отступы в четыре пробела. Сохраняйте типизацию и стиль соседнего кода; функций и переменных придерживайтесь `snake_case`, классов — `PascalCase`, тестов — `test_<поведение>`. Комментарии, пользовательские тексты и документация пишутся по-русски; названия технологий и вариантов голов (`rnnt`, `e2e_rnnt`) не переводятся. Форматтер и линтер не настроены.

## Тестирование

Используются `pytest` и `pytest-asyncio`; тесты автоматически ищутся в `tests/`, асинхронные фикстуры работают в режиме `auto`. Набор не требует движка, скачивания весов или сети: поведение проверяется через заглушку и ASGI-клиент. Для каждой функциональной правки добавляйте узкий тест, затем запускайте весь `uv run pytest`; обязательного порога покрытия нет.

## Архитектура и конфигурация

`main.py` связывает `Settings`, `Supervisor`, управляющий API `/api`, OpenAI-совместимый фасад `/v1` и статику. `data/state.json` сохраняет развёрнутую конфигурацию и после первого запуска имеет приоритет над `.env`. Секреты держите только в `.env`; не добавляйте в Git ключи, веса, состояние и аудиофайлы. `GIGASTT_TAG` меняйте только вместе с проверкой совместимости и ручным smoke-тестом.

## Коммиты и pull request

История использует короткие повелительные сообщения в Sentence Case без Conventional Commits, например `Close the API schema behind the same key...`. В PR опишите изменение и проверенные команды, укажите затронутую конфигурацию или риски безопасности, приложите снимки экрана для изменений UI и ссылку на задачу, если она есть. Для изменений Docker, движка или API добавьте результаты соответствующей ручной проверки и обновите `README.md`/`docs/`, если поведение изменилось.
